# Bun Migration Findings

## Purpose and scope

Research findings gathered while planning the npm-to-bun migration. Task documents under `plan/phase-01-migrate-to-bun/` cite this note.

## Current state (as surveyed)

- `package.json`: scripts delegate to `make`; devDependencies include `jest` and `@liquid-labs/sdlc-resource-jest` (to remove); no `jest` key; `_sdlc.linting.ignores` is the only `_sdlc` content (no jest config); `engines.node >=18.0.0`; `files: ["dist/"]`; `prepack`/`preversion` hooks call `make`.
- No `jest.config.*` in the repo. Jest config came from `@liquid-labs/sdlc-resource-jest/dist/jest.config.js` via the Makefile (`--config`, `SRJ_CWD_REL_PACKAGE_DIR`, `NODE_OPTIONS=--experimental-vm-modules`). That config sets `collectCoverage`, reporters `json,text,html,clover`, and coverage ignore patterns (`/test/`, `*.test.*`, `index.*`, `dist`, `qa`, `coverage`).
- Makefile npm/jest touch points: `npm explore @sdlcforge/packjs -- pwd` (twice), `npx rollup`, `npx jest`, `npm explore @liquid-labs/sdlc-resource-jest -- pwd`, `npx jsdoc2md`, and `cp -r ./coverage/* qa/coverage`.
- Tests: 11 `*.test.mjs` files plus helpers under `src/**/test/` (`src/test/lib/*.mjs`, `src/lib/lib/test/mock-read-file.mjs`). They use jest globals (`describe`, `test`, `test.each`, `expect`, `beforeAll/Each`, `afterEach/All`), extensionless relative imports, `import.meta.url`, and `@jest/globals` in two files (`mock-read-file.mjs`: `jest.fn`, `jest.unstable_mockModule('node:fs/promises')`; `process-gitignore.test.mjs`: `jest.spyOn(process.stderr, 'write')`). Four tests import `./mock-read-file` (`extract-patterns-from-file`, `process-file-patterns`, `process-package-ignores`) and rely on the module mock.
- Shipped lint config: `src/lib/default-config/eslint-components/tests.mjs` applies `globals.jest` to consumer test files. This is consumer-facing behavior, not a dev-tooling detail.
- `scripts/release.sh` uses npm for `npm version` (runs the `preversion` hook), `npm whoami`, `npm view`, `npm pack --dry-run`, `npm publish`, and git-adds/checks-out `package-lock.json`.
- `.readme-assets/coverage.svg` and `.sdlc-data.yaml` hold a coverage badge generated by an external sdlc badge builder from jest coverage output; not part of this plan (filed as a followup).
- Tracked-file mentions of npm/jest: `README.md` (generated from `src/docs/README.01.md` / `README.02.md`; only a consumer `npm i` line), `RELEASING.md`, `DEVELOPER_NOTES.md` (mentions a babel dependency story, no npm commands), `docs/architecture.md` line ~135 ("Adds Jest global variables"), `src/lib/default-config/eslint-components/tests.mjs` comments, `src/lib/default-config/eslint-config.mjs` (npmjs.com links only; leave). `qa/` is gitignored output; `scripts/` holds only `release.sh`; `coverage/` is gitignored.
- The environment has bun 1.3.14 (text `bun.lock` is the default format) and Node plus npm.

## Decisions

1. **Publishing stays on npm.** `scripts/release.sh` keeps `npm version`, `npm whoami`, `npm view`, `npm pack --dry-run`, `npm publish --access public --tag`. Reasons: the user-run OTP/2FA prompt, dist-tag logic and idempotency checks are built around the npm CLI, and the package is consumed from the npm registry. Only lockfile handling changes (`package-lock.json` references dropped; `bun.lock` carries no package version, so the release commit contains only `package.json`; the task verifies this empirically with a dry run). `npm` remains a release-time prerequisite alongside bun.
2. **Consumer-facing surface is unchanged.** `engines.node`, the `dist/` output, the `#!/usr/bin/env -S node --enable-source-maps` shebang, and the README consumer install instructions (`npm i ...`, `npx fandl`) stay; bun equivalents may be added alongside, not instead. The built output must be byte-equivalent to a pre-migration build modulo any rollup/dependency noise, and Node must still run `dist/fandl-exec.js` and import `dist/fandl.js`.
3. **Bun is the dev runtime**: install (`bun install`, `bun install --frozen-lockfile`), script runner (`bunx` for rollup/jsdoc2md), and test runner (`bun test`). The existing `package.json` scripts keep delegating to `make`.
4. **Lock migration order.** Run `bun install` while `package-lock.json` still exists so bun migrates the resolved versions, then delete `package-lock.json`.
5. **Test globals.** Keep `describe/test/expect/beforeAll/...` as bun globals (bun provides them without imports), so the shipped lint config needs no change; import `mock`/`spyOn` explicitly from `bun:test` only where needed. Do not change `globals.jest` in the shipped `tests.mjs` (it is a superset of the names bun:test exposes and consumers still run jest); update comments only.
6. **Module-mock isolation risk.** `bun test` runs all files in one process, and `mock.module` registrations are not reliably undone between files (a quick experiment showed a mocked `node:fs/promises` visible to an unrelated test file). Preferred fix: remove `mock-read-file.mjs` and test `extractPatternsFromFile`, `processFilePatterns`, `processPackageIgnores` against real fixture files (the latter needs the cwd to contain a `package.json`; use a temp dir plus `process.chdir`, restored afterward). Fallback only if that proves impractical: keep `mock.module` and run those files in separate `bun test` invocations from the Makefile.
7. **Scope `bun test` to `./src`.** The project root contains `worktrees/` (copies of the repo with their own tests) and bun's discovery would otherwise pick them up. Use a `bunfig.toml` `[test]` section (root, coverage ignore patterns excluding test files and `index.*`) or explicit path arguments, plus `--coverage` with `--coverage-dir qa/coverage`.
8. **Latent defect noted, not fixed here:** `src/lib/lib/process-package-ignores.mjs` reads `package.json:devPkg.linting.ignores`, whereas `package.json` uses `_sdlc.linting.ignores`. Filed as a followup.
